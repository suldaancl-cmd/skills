# System Design 101 Local

Primary references:

- Bundled categories: `references/data/categories`
- Bundled guides: `references/data/guides`
- Original clone: `C:\tmp\system-design-101`

## When To Use

Use this skill when a task asks about:

- System design interviews.
- API design, load balancing, proxies, gateways, caching, storage, queues, consistency, sharding, CDNs, observability, reliability, or scaling.
- Explaining complex systems with visuals and simple terms.
- Comparing architecture options or preparing a system-design answer.

## Workflow

1. Start from `references/data/categories` for the topic map.
2. Search `references/data/guides` for the specific mechanism, pattern, or case study.
3. Explain the system in plain language before naming advanced patterns.
4. Separate requirements, high-level design, data model, request flow, scaling bottlenecks, and tradeoffs.
5. Prefer diagrams or diagram-ready descriptions when useful.
6. Include practical failure modes and mitigation strategies.

## Output Shape

For interview-style answers, use:

1. Requirements and constraints.
2. High-level architecture.
3. Core flows.
4. Storage and data model.
5. Scaling and reliability.
6. Tradeoffs and follow-up talking points.

For learning explanations, keep the answer short, visual, and example-driven.
